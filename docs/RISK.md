# 项目潜在风险说明

## 1. 第三方解析接口不稳定

### 风险描述

项目核心功能（视频解析）依赖外部聚合接口（BugPK、龟龟呀、HelloTik 等），这些接口存在内在不确定性：

| 风险点 | 说明 | 已证实案例 |
|--------|------|-----------|
| 免费端点波动 | BugPK 免费线路无 SLA 保障，随时可能不可用 | 小红书解析（TC-004）：BugPK 所有端点均失败 |
| API 变更 | 第三方可能调整返回结构、鉴权方式或限流策略 | — |
| 平台反爬升级 | 抖音/快手等平台可能调整分享链接格式或加强反爬 | 抖音 CDN 拒绝云函数 IP 下载（`download_failed`） |
| 链路退化 | 多 fallback 掩盖了单点失效，但不等于解决了问题 | BugPK 禁用后，部分平台直接无法解析 |

### 当前缓解措施

- **多供应商 fallback**：BugPK → 龟龟呀 → HelloTik → 内置线路，任一成功即返回
- **环境变量切换**：`BUGPK_DISABLE=1`、`GUIGUIYA_STRICT=1` 等可灵活开关线路
- **自定义接口**：`VIDEO_PARSE_URL` 支持接入商用 API，绕过免费线路

### 建议

- 生产环境配置 `VIDEO_PARSE_URL` 商用解析接口（独享线路 / SLA）
- 监控云函数日志中供应商错误码分布，及时切换失效线路
- 对关键平台（抖音/快手）设置解析成功率告警

## 2. 云存储上传限制

### 风险描述

解析后的视频需要从第三方 CDN 下载并上传至微信云存储，两个环节均存在限制：

| 风险点 | 限制值 | 影响 |
|--------|--------|------|
| 单文件上传上限 | 默认 20MB，最大 50MB（`EXTRACT_MAX_UPLOAD_MB`） | 超过限制的视频无法转存，仅返回直链 |
| CDN 防盗链 | 抖音、B站等 CDN 拒绝非浏览器请求 | 云端下载失败，用户需手动从浏览器下载（抖音 TC-001 实测） |
| HLS 流分片上限 | 200 个分片 | 长视频/直播流无法处理 |
| 短视频阈值 | 25MB（`SHORT_VIDEO_MAX_MB`） | 低于阈值跳过云存储，前端直连源 CDN，但链接可能过期 |
| 云存储费用 | 按存储量 + 下载流量计费 | 大量视频转存会增加云开发费用 |

### 当前缓解措施

- `uploadSkipReason` 返回具体原因（`short_video` / `download_failed` / `file_too_large`），前端据此给出不同引导
- B 站强制走云端转存（`platformRequiresCloudUpload`），避免前端直连 CDN 失败
- `EXTRACT_SKIP_UPLOAD=1` 可全局关闭云端转存

### 建议

- 超过 50MB 的视频引导用户使用视频压缩功能或分段处理
- 关注云存储费用增长，评估是否需要设置 `EXTRACT_SKIP_UPLOAD`
- 对高频直链失效的平台（如抖音），优先配 `VIDEO_PARSE_URL` 获取更稳定的 CDN 地址

## 3. 异步任务超时

### 风险描述

云函数默认超时 60 秒，多线路 fallback + 下载上传的累积耗时可能触及此上限。

| 风险点 | 说明 | 缓解 |
|--------|------|------|
| 解析超时 | 多供应商 × 各 3 次重试 → 时间叠加 | `EXTRACT` 超时已调至 85s，云函数配置 300s |
| 下载超时 | 大文件直链下载慢 | 重试机制 + 短视频跳过策略 |
| 轮询超时 | 语音识别等异步服务排队时间长 | 轮询间隔自适应（1s → 2s → 3s → 5s） |

## 4. 环境变量依赖

### 风险描述

功能可用性高度依赖环境变量配置，缺失时表现各异：

| 环境变量 | 缺失影响 |
|----------|---------|
| `TCB_ENV_ID` | 云函数无法初始化 |
| `TENCENT_SECRET_ID` / `TENCENT_SECRET_KEY` | 文案转写不可用 |
| `GUIGUIYA_API_KEY` | 龟龟呀线路跳过，不影响其他线路 |
| `VIDEO_PARSE_URL` | 自定义接口跳过，降级为内置免费线路 |
| `HELLOTIK_API_TOKEN` | HelloTik 线路跳过 |

**建议**：部署后运行 `test/requestVideoJob.json` 中的用例验证核心链路，确保最少环境变量可用。
