# 缺陷与展望

## 当前性能

### 多平台视频解析

单个 30 秒至 1 分钟的短视频（抖音/快手/小红书）从粘贴链接到出现预览通常 3-10 秒。B站视频因需下载合并 HLS 分片，5 分钟视频可能耗时 30-60 秒。

**限制因素**：第三方免费 API 无 SLA 可能超时；多供应商 fallback 增加容错但拉长最坏情况延迟；B站 m3u8 分片合并同步占用云函数；Akamai CDN 防盗链无法 100% 绕过；云存储免费环境单文件上限 10MB。

### 视频预览与保存

解析完成后视频立刻出现在页面上播放（使用远程 URL，不等本地下载）。后台静默下载到本地持久化，1 分钟视频约 30-60 秒完成。点击保存时复用后台下载结果，避免重复下载。

**限制因素**：`wx.downloadFile` 对非白名单域名（第三方 CDN）无法下载，必须经过云存储转存；大文件下载受用户手机网络带宽制约；已通过进度条改善等待体验，但无法缩短下载时间。

### 视频压缩

本机压缩（`wx.compressVideo`）在用户手机上执行，不占用云函数资源。3 档品质 + 高级自定义参数，压缩速度取决于用户手机性能和视频时长，1 分钟视频通常在 30 秒至 2 分钟内完成。

云端压缩（COS 数据万象）提交后异步执行，转码排队 + 执行时间取决于视频大小和腾讯云资源，通常 2-10 分钟。

**限制因素**：本机压缩受用户设备性能限制，低端手机可能较慢或压缩失败回退原片；COS 云端压缩需要额外配置密钥和 Bucket，增加运维成本；长视频（>2分钟）本机压缩耗时显著增加。

### 提取文案（ASR）

提交音频/视频文件到腾讯云录音文件识别，异步返回结果。1 分钟音频通常 5-30 秒出结果，最长支持数小时内容。前端默认轮询间隔递增（1s → 2s → 5s），平衡延迟与云函数调用次数。

**限制因素**：依赖腾讯云 ASR 服务可用性；需配置 `TENCENT_SECRET_ID/KEY`；仅支持中文普通话（`16k_zh` 引擎）；长音频（>1 小时）轮询次数多，可能触及 1000 次轮询上限。

### MD5 变更

在云函数侧读取云存储文件，追加 MP4 `free` 原子后回传。纯内存操作，48MB 以内文件通常 5-15 秒完成。

**限制因素**：云函数内存限制 256MB，文件需全部读入内存，48MB 上限已接近安全边界；大文件操作期间云函数内存压力大。

### 积分与广告

签到和积分操作为轻量数据库读写，通常 <500ms。激励视频由微信客户端渲染，不受项目代码控制。

**限制因素**：广告填充率取决于微信广告平台，可能出现无广告可播的情况；积分为简单累加逻辑，无事务保障，极端并发下可能存在数据不一致。

## 当前缺陷

### 1. B站下载不稳定

B站视频直链多为 Akamai CDN 分发，防盗链严格。云函数侧即使模拟了桌面 UA + Referer，仍有较大概率遇到 403。HLS 分片下载虽然已加入重试机制，但分片 URL 时效性极短（可能仅数十秒），长视频下载到后面分片时 URL 已过期。**目前 B站解析成功率依赖于 BugPK 返回的链接有效期和 CDN 节点状态，不可控因素多。**

### 2. 大文件上传受限

微信云存储免费环境单文件上传上限 10MB，标准版 20MB。超过此限制的视频无法转存，只能引导用户复制直链到浏览器下载。对于高清长视频，这个限制很致命。云端转码（COS 数据万象）虽然能生成小体积版本，但需要额外配置且增加延迟和费用。

### 3. 解析依赖第三方免费服务

BugPK、devtool、TenAPI 等均为免费聚合接口，无 SLA 保障。随时可能限流、改版、下线。虽然设计了多供应商 fallback，但如果所有免费接口同时故障，核心功能立即瘫痪。接入商用解析 API 需要付费且各家接口协议不统一。

### 4. 没有服务端任务队列

所有解析和下载操作都在云函数单次调用内同步完成。长视频的 HLS 下载合并可能耗时数分钟，占用云函数并发配额。理想架构应是：接收请求后立即返回任务 ID，后台队列异步处理，前端轮询结果。

### 5. 错误信息对用户不够友好

虽然已通过 `messages.js` 集中管理消息文案，但部分底层错误（如 axios 网络异常、云函数超时）抛到前端的仍然是技术性描述。缺少面向普通用户的通俗解释和明确的下一步操作指引。

### 6. 前端缺少加载和空状态优化

部分页面在数据加载中或列表为空时，展示较为简陋。骨架屏、空状态插图等体验细节尚未完善。

### 7. 缺乏自动化测试

云函数和小程序前端均无单元测试或集成测试。解析链路的修改只能依赖手动测试，回归成本高。

## 下一步展望

### 短期（可立即执行）

- **yt-dlp 独立解析服务** — 部署 yt-dlp 为独立 HTTP API（腾讯云 SCF Python 运行时 / 云托管容器），替代当前 BugPK 单点依赖。yt-dlp 原生支持抖音、B站、小红书，内置浏览器指纹伪装可解决 B站 Akamai 403。架构：`云函数 → HTTP → yt-dlp API → 返回直链`。可直接解决缺陷 #1 和 #3。
- **前端骨架屏** — 在历史列表、任务面板等加载状态下加入骨架屏

### 中期（需要一定工作量）

- **后端服务重构** — 当前所有业务逻辑集中在单一云函数 `quickstartFunctions` 中，解析、下载、ASR、压缩、积分全部耦合在一起。计划使用 Go 或 Python 等更适合后端服务的语言重写核心模块，拆分为微服务架构：解析服务（Python + yt-dlp）、媒体处理服务（Go/Node.js）、用户服务（积分/签到/频控）各自独立部署。服务间通过 HTTP 通信，不同模块可根据性能需求选择最合适的语言，各自独立扩缩容。
- **异步任务队列** — 将云函数拆分为「提交任务」和「查询结果」两个独立调用，中间通过云数据库状态字段 + 定时触发器解耦
- **COS 数据万象深度集成** — 所有超过云存储上限的视频自动触发 COS 转码，生成适配版本后回传

### 长期（架构升级）

- **自建解析 Worker** — 脱离第三方聚合接口，直接对接各平台官方 API 或自维护解析逻辑
- **多端适配** — 将解析能力封装为独立 API，支持小程序以外的渠道（公众号 H5、App 内嵌 WebView）
- **用户内容管理** — 解析记录云端同步、收藏夹、标签分类
- **测试体系** — 云函数单元测试（Jest）+ 小程序端到端测试（miniprogram-automator）
