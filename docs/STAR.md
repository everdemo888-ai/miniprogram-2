# 项目说明

> 这是我的个人项目，从零开始独立完成，包含前端小程序、云函数后端、第三方服务集成和工程化整理。

## 一句话概括

一个微信小程序，用户粘贴抖音/快手/小红书/B站等平台的分享链接，一键解析出无水印视频并保存到手机相册。附带视频压缩、语音转文字、MD5 变更等工具。

---

## Situation — 为什么要做

短视频平台出于版权和流量保护，会给视频打上水印，且不提供下载按钮。用户想保存喜欢的视频到手机，只能借助第三方工具。但市面上现有的去水印工具大多需要下载独立 App、注册、看广告甚至付费。

我的想法是：**微信小程序是最合适的载体**。用户不用安装、不用注册，打开微信就能用，用完即走。配合微信云开发，连服务器都不用自己搭。

## Task — 我给自己定的目标

核心指标很明确：用户粘贴一条分享链接，点一下按钮，十几秒内看到无水印视频，并且能保存到相册。

在此基础上，我希望这个小程序做到：
- 支持至少五个主流平台（抖音、快手、小红书、B站、视频号）
- 附带常用视频工具，不做「用完即走的一次性工具」
- 通过激励广告 + 签到积分实现免费使用，用户不用担心付费门槛
- 代码质量能达到面试展示水平——分层清晰、无硬编码、有文档

## Action — 怎么做的，以及背后的思考

### 1. 多供应商解析链路

**问题**：视频解析不像调用一个 API 那么简单。免费解析服务不稳定——今天能用明天可能就挂了；即使同一个服务，对抖音链接有效对 B站链接可能完全不行。

**我的做法**：不绑定单一供应商，而是搭了一个 fallback 链路：

```
用户粘贴链接
  → 检测平台（douyin / kuaishou / xhs / bilibili / weixin_channels）
  → 优先走自定义商用接口（环境变量配置，如果有的话）
  → BugPK 聚合接口（按平台选子端点，或统一短视频接口）
  → 龟龟呀（仅抖音，需 API Key）
  → HelloTik（需 Token）
  → 各平台内置线路（devtool → TenAPI → TJIT → 多个 POST/GET 变体）
  → 小红书/B站额外补试专用端点
```

单次解析最多尝试 12 个以上的端点。任一环节成功就返回，全部失败才给用户报错。**每个端点都是环境变量可覆盖的**，意味着如果哪天我接入了商用解析 API，只需配一个环境变量就能切换，不用改代码。

**思考**：这个设计牺牲了一点延迟（多试几个 fallback），但换来了可用性。对于用户来说，等 5 秒看到视频比秒级报错「解析失败」好得多。

### 2. B站 HLS 流的下载合并

**问题**：B站是五个平台里最难处理的。BugPK 返回的视频链接通常是 m3u8 播放列表而不是 mp4 文件。如果直接下载，只能拿到一个几百字节的文本文件，用户当然看不了。

更深层的问题是 B站 CDN 用的是 Akamai，防盗链极严。我试了多种方案：
- 带 `Referer` + `Origin` → 403
- 加 `Range: bytes=0-` → 403
- 换桌面端 Chrome UA → 403
- 去掉 Origin（Akamai 有时对有 Origin 无 Cookie 的请求直接拒）→ 仍然不稳定

**我的做法**：既然 B站直链下载不可靠，就不在客户端下。在云函数侧做了完整的 HLS 处理：

```
检测到 m3u8 URL
  → 下载播放列表（3次重试）
  → 解析所有 ts 分片 URL
  → 并发下载分片（每次3个，单个分片失败自动重试2次）
  → 合并为完整 mp4 Buffer
  → 上传微信云存储
  → 前端从云存储获取 → 预览和下载
```

如果合并后的视频超过云存储上传上限（免费版 10MB / 标准版 20MB），就告诉用户具体原因并引导复制直链到浏览器。

**思考**：这个模块是整个项目里技术挑战最大的部分。它涉及流媒体协议理解、并发下载控制、错误重试策略、CDN 防盗链对抗。虽然还不是 100% 可靠（详见 ROADMAP），但已经能在大多数情况下工作。

### 3. 小程序端的下载体验优化

**问题**：用户在解析完成后点「保存到相册」，要等整个视频下载完才能存。长视频可能要等一分钟以上，体验很差。

**我的做法**：

1. **解析完成即显示** — 用云存储临时链接直接给 `<video>` 组件播放，不等下载
2. **后台静默下载** — 同时启动 `wx.downloadFile` 下载到本地并 `saveFile` 持久化
3. **保存按钮复用后台下载** — 用户点保存时，如果后台下载进行中，直接等它完成而不是启动第二个下载抢带宽；如果已完成，瞬间保存
4. **实时进度条** — `DownloadTask.onProgressUpdate` 拿到下载百分比，渲染进度条替代 loading 遮罩
5. **平台感知** — B站/视频号等需要云存储转存的平台，如果转存失败，不尝试用原始直链（必然失败），而是弹窗引导用户复制直链到浏览器

**思考**：这些改动都是纯前端的，不需要改后端，但体验提升很大。面试的时候我一般会强调：好的用户体验不一定是炫酷的动画，而是让用户少等、不困惑。

### 4. 工程化整理

这个小程序一开始是从微信云开发模板起步的，随着功能增加，代码开始出现重复和硬编码。我专门花时间做了整理：

- **代码分层**：云函数按职责拆到 `parsers/`、`media/`、`guards/` 三个子目录，一目了然
- **消除硬编码**：创建 `config.js`（超时、截断长度、上传限制等 40+ 个常量）和 `messages.js`（50+ 条用户可见消息），改一处全局生效
- **前端公共模块**：三个页面重复的 `ensureCloudEnv`、`getActionName`、`getJobStatusLabel` 抽取到 `utils/`
- **消除云函数名硬编码**：`"quickstartFunctions"` 字符串在 10+ 处出现，统一为 `CLOUD_FUNCTION_NAME` 常量
- **文档**：STAR、ROADMAP、TECH_STACK 三份文档，README 简洁够用

## Result — 做到了什么

- 支持 **5 个平台**（抖音/快手/小红书/B站/视频号），单次解析最多 **12+ 端点** fallback
- 视频压缩 **3 档品质 + 高级自定义参数**（码率/fps/分辨率），长视频自动识别并推荐省流档位
- 腾讯云 ASR 语音转文字，支持最长数小时的音频
- 激励视频 + 签到积分，完整观看广告获得积分，积分可跳过广告，形成**免费使用闭环**
- **所有密钥走环境变量**，代码仓库零泄露风险
- **7 个云函数模块、5 张数据库集合、8 个第三方服务**，清楚记录在 TECH_STACK

## 性能与规模化思考

虽然目前是个人项目、用户量不大，但我在设计时考虑了这些问题。：

### 当前架构的瓶颈

**云函数并发限制**。微信云开发免费环境云函数并发上限约 20。如果有用户同时提交解析任务，云函数实例不够用，后来的请求会排队或失败。

**B站 HLS 下载耗时**。一个 5 分钟 B站视频可能有 50 个 ts 分片，每个分片下载约 1-2 秒，并发 3 个需要约 30-40 秒才能合完。这期间云函数一直在跑，占用一个并发槽位。

**云存储上传限制**。免费环境单文件 10MB，很多高清视频直接超限。

### 如果要面对 1000 并发用户

1. **异步任务队列** — 当前云函数同步执行解析+下载+上传。改造为：收到请求立即写入数据库并返回 jobId → 云函数定时触发器扫描待处理任务并逐个执行 → 前端轮询结果。这样云函数不会被长任务占满，并发能力取决于数据库轮询频率而非长连接数。

2. **B站走 COS 数据万象转码** — 不在云函数里下载分片，而是将 m3u8 URL 提交给 COS 数据万象的媒体处理任务，由腾讯云基础设施完成转码和转存。云函数只需发起任务和轮询结果，执行时间从分钟级降到秒级。

3. **云存储分层** — 小文件走云存储直传（当前方案）；大文件走 COS 转码生成低码率版本（480p/500kbps），体积通常可降至原来的 1/5 到 1/10。用户如果需要高清版，引导复制直链到浏览器下载。

4. **读多写少优化** — 历史记录和任务状态查询加数据库复合索引（当前已有 `openid + createdAt`），热点数据加云函数内存缓存减少数据库读取。

### 监控与可观测性

当前通过 `console.log` 输出结构化日志（tag + ts + 字段），可在云开发控制台检索。如果要投产，我会补充：

- **云函数耗时分布** — 在 `index.js` 入口处记录每个 `event.type` 的执行时间，统计 p50/p99
- **解析成功率按平台分** — 每个供应商端点成功/失败计数，识别哪个服务在劣化
- **用户行为漏斗** — 粘贴链接 → 点击提取 → 解析成功 → 保存到相册，每步转化率
- **告警** — 解析失败率超过阈值（如 30%）时触发微信告警群通知

### 成本控制

微信云开发按调用次数和资源消耗计费。当前的优化措施：

- **递增轮询间隔** — 前 3 次 1 秒、4-10 次 2 秒、之后 5 秒，避免无效高频查询
- **只上传必要文件** — 解析结果视频才上传云存储，文案提取和 MD5 修改的结果不占用额外存储
- **第三方 API 调用去重** — 同一链接短时间内重复提交，前一次结果缓存可用

### 安全

- 所有数据库操作带 `openid` 校验，用户只能操作自己的任务和积分
- 任务创建加了 24 小时滚动窗口频控（默认 120 次/天），防止恶意刷接口
- 广告积分每日发放次数有上限（默认 40 次/天），防止积分通胀
- 第三方 API Key 全部走云函数环境变量，小程序端代码没有任何密钥
- 云函数 `urlCheck: true`，小程序请求域名白名单校验
